# Dependency patches

`@noble/curves@2.2.0` is a direct build dependency because `build/vendor.mts` copies its root package into the extension. The same version satisfies `micro-eth-signer@0.19.0`; it is the sole installed curve-library version. Application and test code do not import Noble curve APIs directly.

`@noble/curves@2.2.0.patch` adds the locally defined `ERR_SECP256K1_INVALID_POINT` code at the existing secp256k1 non-residue and recovered-infinity errors. Point decoding preserves the square-root error as `cause`. TypeScript and distributed JavaScript agree; arithmetic is unchanged. This code is our patch contract, not an upstream Noble API. The pinned upstream recovery API throws untyped errors for expected invalid points; the narrow patch avoids broad catches, diagnostic-string matching and application-owned curve arithmetic. Prefer an upstream typed invalid-point result when one is available, replacing this adapter integration and its patch together.

`ethereumRecoveryBackend.ts` is the sole adapter for dependency-specific recovery behavior. It delegates to `micro-eth-signer`, translates the local code/cause metadata into a typed success/failure result, and propagates untagged exceptions. `ethereumSigning.ts` consumes that result without knowing the dependency tag or nesting. No human-readable diagnostics control recovery. The adapter also probes both invalid-point outcomes once on first recovery in the shipped extension: an unpatched or incompatible backend fails before recovery is used even when a custom build bypasses the preflight. It cannot silently turn a skipped authorization into an unclassified invalid-point failure in nonce accounting.

`check:recovery-dependency` resolves micro from the actual adapter module, then resolves Noble relative to that micro copy. It checks the micro and direct Noble pins, requires recovery and the root package copied by vendoring to resolve to the same real directory, verifies the patch declaration, and probes both invalid-point outcomes through that same adapter. The adapter and its import-free `runtimeTypeGuards.ts` dependency are intentionally environment-neutral shared modules: they must not acquire browser, extension or application-service imports. Build tooling imports this boundary to test the actual shipped implementation rather than a parallel build-only recovery path. Tests, typecheck and extension compilation run this guard before proceeding. The vendor implementation itself runs it before deleting or copying output, including when invoked directly. Hoisting is accepted when recovery and vendoring share the same package tree; a version, source-copy or tag mismatch fails before output is copied or a bundle is produced.

Bun applies the patch through `patchedDependencies` in `package.json` and `bun.lock`; Docker copies it before the frozen install. For every micro or Noble upgrade: inspect the upstream recovery and point-decoding changes, explicitly rebase/remove the patch in both TypeScript and distributed JavaScript, update the exact pins and frozen lockfile, then run the guard, recovery/nonce tests and required repository validation. Retain the runtime probes unless the adapter uses an upstream typed invalid-point result. Both explicit build preflight and the first recovery call enforce the behavior before it can be used; importing unrelated hashing/encoding primitives does not run recovery probes. The invalid-point tests enforce the tags; an oversized-input test enforces propagation of untagged library failures.

## Recovery patch removal tracking

Tracked by this entry at the adapter boundary. Upstream target: [noble-curves recovery API](https://github.com/paulmillr/noble-curves/blob/main/src/abstract/weierstrass.ts); check [upstream recovery discussions/issues](https://github.com/paulmillr/noble-curves/issues?q=is%3Aissue+recovery) on every dependency upgrade. No specific upstream typed-result issue was found in the current audit; this entry does not claim an upstream fix is scheduled.

Removal criteria: upstream exposes a documented typed result for both non-curve recovery points and recovered infinity, unexpected errors still propagate, and micro-eth-signer exposes or preserves that result. Then replace this adapter integration, remove the patch and patchedDependencies together, and retain both invalid-point and unexpected-error regressions. Until then, updates must rebase and validate both source TypeScript and distributed JavaScript; neither copy may be dropped from the patch.
